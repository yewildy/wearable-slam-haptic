September 2026 - Background
I returned to the wearable SLAM setup after the summer break. This is the background to the project; the Python filtering code below was written in October.

2026-10-27 - Receiving and filtering points
I worked through how Subscriber calls on_cloud(message), and how the XYZ array reaches filter(). A direct Python function test is different from sending and receiving ROS messages.
I added a loop that keeps points farther than 0.50 m. For the four-point example, 0.80 m and 1.20 m remain. An empty result still has shape (0,) rather than (0, 3); this needs tidying up.

2026-10-27 - Connecting the real LiDAR
At first the node received nothing. The launch argument still selected the simulated input, overriding the default topic in the code. Restarting with /livox/lidar fixed the connection.

2026-10-27 - Returning the nearest distance
I added filter_logic_closer_num.py. It starts the minimum at inf, updates it when a closer retained point is found, and returns both the cloud and the distance. The caller unpacks them into kept and min_distance.
The distance is now printed in the terminal, not published on a separate topic. No retained points means inf, which must not be read as a safe, clear area.

Next
Try mapping distance to alert strength with a simple linear function. Thresholds and missing-data handling still need to be decided. No motor test or quantitative accuracy evaluation has been done for this version.

2026年9月 - 背景
暑假后重新回到可穿戴SLAM装置的研究。这部分是项目背景，下面的Python过滤代码是在10月编写的。

2026-10-27 - 接收和过滤点云
理清了Subscriber如何调用on_cloud(message)，以及XYZ数组如何传入filter()。直接调用Python函数测试，和通过ROS收发消息测试，是两回事。
用循环保留大于0.50 m的点。四点例子中留下0.80 m和1.20 m。全部删除后数组形状还是(0,)，不是(0, 3)，这点还需要整理。

2026-10-27 - 接入真实雷达
开始收不到消息，原因是启动参数仍然选择模拟输入，覆盖了代码里的默认话题。用/livox/lidar重新启动后连接成功。

2026-10-27 - 返回最近距离
新增filter_logic_closer_num.py，把最小距离初始值设为inf，找到更近的保留点就更新，最后一起返回点云和距离。调用处用kept和min_distance解包。
目前距离打印在终端，没有单独发布话题。没有保留点时返回inf，不能把它当作周围没有障碍。

下一步
先尝试把距离线性换成提醒强度。阈值和没有有效数据时的处理还没决定。本版本还没有进行马达测试或定量精度评价。
