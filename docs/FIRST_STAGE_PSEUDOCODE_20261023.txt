# 第一阶段点云处理伪代码详解

本手册解释当前第一阶段的三个 Python 文件：initialization_candidates.py、review_self_mask.py、audit_mask_risk.py。目标是让你能说出每个函数拿到什么、怎样计算、返回什么，以及三个文件怎样合作。先按中文步骤读懂思路，再对照函数名阅读源码。

当前流程是离线原型：从已保存的近点中提取稳定候选，经逐格审核后，预览哪些点会被排除。它还没有自动识别身体，也没有连接成实时 ROS 自身过滤节点。这里的教学坐标和标签都是为了演算而构造，不是对真实装置的身份标定。

伪代码是把真实实现展开成人容易理解的步骤，不能直接复制运行。有些真实 NumPy 语句一次处理整批点，本手册将其写成循环解释；展开后的循环不代表建议把现有实现改慢。

# 1 先把整体流程看明白

## 1.1 三个文件不是三个必须同时运行的节点

第一阶段主要由两个工具承担功能，另一个旧工具提供检查函数。它们目前不是通过 ROS 话题互相传递候选，而是使用内存中的函数调用以及 NPZ、JSON 等文件交接数据。

| 文件 | 在新流程中的主要作用 | 单独运行时做什么 |
| initialization_candidates.py | 找稳定近点候选 | 读取 NPZ，输出候选 JSON 和 CSV |
| review_self_mask.py | 生成审核页并预览排除 | 用 page 或 preview 子命令选择路线 |
| audit_mask_risk.py | 提供 checked_sample 输入检查 | 另有旧局部盒的独立风险审查流程 |

特别注意：新初始化程序会导入 audit_mask_risk.py 的 checked_sample 函数，不是启动另一个 audit 进程，也不会因此自动执行旧盒子审查。

```text
准备阶段：原始 bag 经采样分析工具导出 near_returns.npz

运行初始化程序
    调用 checked_sample 检查数据
    调用 analyze 统计稳定近点
    保存 candidate_review.json 和 candidate_voxels.csv

运行审核工具的 page 模式
    读取候选和同一份 NPZ
    生成 HTML 审核页面

人在浏览器中逐格决定
    自身 SELF / 外物 EXTERNAL / 未确认 UNSURE
    导出 self_review_decisions.json

运行审核工具的 preview 模式
    检查决定与候选是否对应
    生成默认关闭的审核配置
    计算保留、排除、无效点标记
    保存配置与统计，不改写原始点云
```

## 1.2 现在实际实现到了哪里

“稳定”表示某个雷达局部位置在一段时间里经常有回波。“自身”表示你有依据认为它属于身体、支架或固定线缆。“排除”表示按照选定几何范围，决定哪些点不参加后续判断。这三件事不能合并成一个结论。

程序已经能找稳定候选、检查人工审核资料，并计算局部排除结果。真实候选还没有完成身份审核，实时 ROS 接口也未接上。速度、震动强度、马达以及 Point-LIO 位姿补偿不在这三个文件的当前功能内。

## 1.3 和原来的 C++ 有什么关系

原来的 pcl_proximity_node.cpp 是实时订阅点云、计算距离等级的节点。这里的新 Python 工具还没有把审核后的体素配置送给它。原 C++ 用的是局部盒 self_boxes，新 Python 审核配置使用 self_voxels，二者不是同一种配置，不能直接交换文件。

这三个 Python 工具目前通过 python3 直接运行，没有统一加入现有 CMake 启动链。不要因为运行了原来的 pcl_proximity.launch，就以为这套 10 秒初始化也已经启动。

# 2 先认识数据和程序入口

## 2.1 点与帧

一个点有三个坐标 [x, y, z]，单位是米。这里的原点是雷达原点。不能未经安装核对，就把 X 正方向说成身体正前方。

一帧是一条点云消息，包含很多点。这里统计的是“某一小格在多少帧出现过”，不是“这一小格累计出现多少个点”。如果一帧里同一格有 100 个点，也只算这一帧出现过一次。

## 2.2 NPZ 里四个关键数组

NPZ 可以理解成一个装着多个数组的压缩容器。当前 near_returns.npz 只包含约 0 至 0.5 m 的有效近点及每帧信息，不是整份 bag，更不是完整环境地图。

| 字段 | 形状和例子 | 含义 |
| xyz | N 行 3 列，例如 [0.205, 0.005, 0.005] | 每一行是一个近点 |
| frame_id | N 个整数，例如 [0, 0, 1] | 每个点来自第几帧，编号从 0 开始 |
| frame_stamps | F 个数，例如 [1000.0, 1000.1] | F 帧各自的时间戳，单位秒 |
| frame_names | F 个字符串，例如 sensor | 每帧使用的空间坐标系名称 |

最容易混淆的是 frame_id：NPZ 的 frame_id 是点所属的“帧序号”；ROS 消息 header.frame_id 通常是空间坐标系字符串，在这个 NPZ 中保存到 frame_names。两者不是同一个概念。

```text
xyz[0] = 第 0 个点的三个坐标
frame_id[0] = 7
因此第 0 个点来自第 7 帧

frame_stamps[7] = 第 7 帧的时间
frame_names[7]  = 第 7 帧的空间坐标系名称
```

某帧没有近点，并不等于这帧不存在。它仍然有时间戳和坐标系名称；出现率的分母仍应包含它，否则候选的稳定性会被高估。

## 2.3 Python 从哪里开始

直接运行脚本时，Python 先执行顶层导入与定义，再到文件末尾的入口判断。函数被 def 定义出来，并不表示已经执行。

```text
当这个文件是被 python3 直接运行的脚本：
    __name__ 等于 '__main__'
    调用 main()

当另一个文件导入这个模块：
    加载它的顶层代码和函数定义
    不调用文件末尾保护起来的 main()
    等调用者主动使用某个函数
```

初始化工具加载旧审查模块后，只把 checked_sample 取出来备用。旧工具的 audit 和 main 不会跟着执行。文件开头缺依赖导致的错误，可能在进入 main 之前就发生，不能理解成 main 会捕获任何启动错误。

## 2.4 输入文件和输出文件不要混用

| 文件 | 用途 |
| near_returns.npz | 点坐标、点所属帧、每帧时间和坐标系 |
| candidate_review.json | 完整候选资料、参数、来源指纹和逐格统计 |
| candidate_voxels.csv | 便于表格查看的索引、中心、出现率，不含全部审核信息 |
| HTML 审核页 | 候选的交互查看界面，需要浏览器打开 |
| self_review_decisions.json | 你对每个候选的决定和理由 |
| reviewed_profile.json | 通过检查的审核配置，仍然默认关闭 |
| preview_summary.json | 会排除多少点、保留多少点等统计 |

CSV 比 JSON 少了一些信息，不能随便拿 CSV 替代 candidate_review.json。最终两个预览输出文件都不是被过滤后的点云文件。

# 3 旧工具提供的输入检查

这一章先讲 audit_mask_risk.py 的 checked_sample，因为初始化和审核页面都需要它。它是数据检查函数，不是自动清洗函数：发现格式或质量条件不满足时通常会报错，而不是悄悄修好再继续。

## 3.1 函数的输入和输出

输入是一个包含数组的 sample，以及期望坐标系 expected_frame。成功时返回统一类型的 xyz、帧序号 ids 和时间 stamps。坐标系数组只用来检查，不在返回的三个数组中。

```text
函数 checked_sample(sample, expected_frame)：
    必须包含 xyz、frame_id、frame_stamps、frame_names
    取出四个数组
    检查坐标数组
    检查点与帧的对应关系
    检查每帧时间与空间坐标系
    全部通过后：
        坐标转成 float32
        帧序号转成 int64
        时间转成浮点数
        返回 坐标、帧序号、时间
```

## 3.2 坐标检查

xyz 必须是 N×3 的数值数组，且不能整份没有点。每个点都必须是有限数，不能包含 NaN 或 Inf，也不能是 [0,0,0]。此外，近点导出中的每个点到雷达原点的距离必须不大于约 0.500001 m。

```text
如果 xyz 不是二维数组，或每行不是 3 个数：报错
如果 xyz 没有点：报错
如果任意坐标是 NaN 或 Inf：报错
如果任意一点三个坐标全为 0：报错

对每个点 p：
    距离 = sqrt(p.x² + p.y² + p.z²)
    如果距离大于 0.500001：报错
```

0.500001 m 是兼顾浮点表示的近点导出范围检查。它不表示“0.5 m 以内全部属于身体”，也不是当前提醒距离阈值。

## 3.3 帧序号检查

```text
frame_id 的长度必须等于点数 N
其中每个元素必须是整数
所有序号必须满足：0 <= 序号 < 总帧数 F
```

例如总共只有 5 帧，合法序号是 0 至 4。一个点写着来自第 9 帧，就无法查询其时间和坐标系，应当报错。

## 3.4 时间和坐标系检查

```text
至少存在 2 帧时间
每个时间必须有限且大于 0
相邻时间必须严格递增

frame_names 数量必须等于时间数量
每个名称必须是字符串
expected_frame 本身必须非空
每帧名称都必须等于 expected_frame
```

时间相等、倒退或坐标系混用都会破坏后续统计。这里检查的是文件内部的一致性，不证明消息刚刚采集，也不能从 NPZ 恢复原消息的声明点数是否正确；那些字段已经不在这份导出里。

# 4 初始化程序逐步翻译

## 4.1 文件开头为什么还要找另一个文件

初始化工具先尝试在自身目录寻找 audit_mask_risk.py，找不到时再去父目录寻找。这样兼容 Jetson 独立工具放在同目录、公开仓库旧工具放在根目录的两种布局。

```text
检查工具路径 = 当前脚本同目录 / audit_mask_risk.py
如果该文件不存在：
    检查工具路径 = 当前目录的父目录 / audit_mask_risk.py
按指定路径加载模块
checked_sample = 已加载模块中的同名函数
```

这是加载依赖，不是远程下载，不会启动雷达。两处都没有文件时需要先补齐正确的工程文件，不能靠更换坐标系或调阈值解决。

## 4.2 函数 validate_parameters

默认设置：初始化 10 s、体素边长 0.02 m、总出现率门槛 0.8、至少 30 帧、最大时间间隔 0.3 s。另一个固定条件是五个时间段的出现率各至少 0.5。

| 参数 | 当前默认 | 接受范围 | 作用 |
| seconds | 10 | 1 至 60 秒 | 初始化窗口时长 |
| voxel_m | 0.02 | 0.005 至 0.1 米 | 小格子的边长 |
| occupancy | 0.8 | 0.5 至 1 | 总帧出现率门槛 |
| min_frames | 30 | 不小于 5 的整数 | 窗口内最少帧数 |
| max_gap | 0.3 | 大于 0 且不大于 1 秒 | 最大允许时间间隔 |

```text
对秒数、格宽、出现率、时间间隔：
    必须是有限数字，不能把 True/False 当数值传入
逐项检查是否位于允许范围
min_frames 必须是普通整数且至少为 5
只要有一项不合格：报错并停止本次计算
```

Python 的 bool 属于 int 的子类，所以代码特意排除了 True/False。这些检查保证参数基本可计算，不表示任何合法参数都适合穿戴设备。

## 4.3 函数 analyze 的阶段一 选时间窗口

```text
调用 validate_parameters
调用 checked_sample，得到 xyz、ids、stamps

每帧相对时间 = 该帧时间 - 第 0 帧时间
如果整段记录不够要求的初始化秒数：报错

选中相对时间 <= seconds + 微小容差的帧
frame_count = 选中帧数量
如果 frame_count 小于 min_frames：报错
```

先检查整段覆盖时长，再取窗口内的帧。10 秒不固定等于 100 帧：如果有 t=0 和 t=10 的端点，就可能得到 101 帧。容差 0.000001 s 用来处理浮点减法误差，不能拿来容许明显缺失的记录。

selected_frame_span_seconds 是最后一个选中帧相对于起点的时间。它有时略小于 10 s，例如最后一帧是 9.9 s，而下一帧是 10.1 s；整段记录仍覆盖窗口末端。

## 4.4 阶段二 检查时间间隔

```text
取初始化窗口内的时间
如果窗口后面还有一帧，把那一帧也加入间隔检查
逐对计算：后一帧时间 - 前一帧时间
求最大间隔 largest_gap
如果它超过 max_gap 加微小容差：报错
```

为什么看窗口外的下一帧？如果 9 s 后断流，直到 15 s 才恢复，不能只看 0 至 9 s 的正常间隔，就认为 10 秒初始化连续完整。

## 4.5 阶段三 分成五个时间段

```text
对每个选中帧：
    段号 = 向下取整(相对时间 / seconds × 5)
    如果段号达到 5，把它压回 4

分别统计段 0、1、2、3、4 有多少帧
任何一段完全没有帧：报错
```

默认 10 s 时，大致对应 0–2、2–4、4–6、6–8、8–10 s 五段。恰在 10 s 的端点被放入最后一段，不建立第六段。每段分母是这段实际存在的帧数，不是固定写成 20。

随后用 ids < frame_count 选点。某帧虽然没有近点，仍在每段帧数中；它只是没有在 xyz 中贡献任何一行。

## 4.6 阶段四 点怎样变成体素索引

```text
对每个选中的点 [x, y, z]：
    ix = floor(x / voxel_m)
    iy = floor(y / voxel_m)
    iz = floor(z / voxel_m)
    此点所属小格 = [ix, iy, iz]
```

格宽为 0.02 m 时，点 [0.205, 0.005, 0.005] 属于 [10,0,0]。这个格子的 X 范围是 [0.20,0.22)，Y 和 Z 范围都是 [0,0.02)。左边界包含，右边界不包含。

点 [-0.205,0.005,0.005] 的 X 索引是 floor(-10.25)=-11，而不是 -10。向下取整与向零截断在负数上不同。格子的中心由 (索引+0.5)×格宽得到，中心不是原始点的平均坐标。

## 4.7 阶段五 按格子和帧去重

```text
建立一个空集合 出现记录
对每个选中点：
    记录 = [ix, iy, iz, 此点的帧序号]
    将记录放入集合
集合内完全相同的记录只保留一次
```

真实代码用 column_stack 和 unique 完成这一步。四列中的最后一列不能丢：同一格在两帧里出现应算两次；同一帧中多点落入同格才需要去重。

接着统计每个格的总出现帧数 hits，以及它分别在五个时间段出现过多少帧 segment_hits。

```text
对去重后的每条记录：
    此格的 hits 加 1
    根据记录的帧序号查出时间段号
    此格在这一段的 segment_hits 加 1
```

## 4.8 阶段六 筛选稳定候选

```text
对每个曾经出现的格子：
    总出现率 = hits / 初始化窗口总帧数
    各段出现率 = 此格各段 hits / 各段总帧数

    如果总出现率 >= occupancy
       并且五段出现率每一个都 >= 0.5：
        把此格加入候选
    否则：不列为候选，但没有删除原始点
```

总出现率 80% 不是“80% 概率属于身体”。它只是帧计数比值。稳定桌面和固定支架都可能通过；移动衣物或落在格子边缘的自身点也可能不通过。

如果初始化窗口内没有任何近点，但整份导出在后续帧有近点，当前函数可以返回 0 个候选。若整份 xyz 为空，则更早的 checked_sample 会报错。这两种情况不同。

## 4.9 阶段七 返回候选资料

每个候选保存 voxel_index、center_m、frames_seen、frame_fraction 和五段 segment_fractions。报告还保存参数、帧数、近点数和质量限制。

```text
返回一个字典：
    kind = initialization_voxel_candidates
    review_state = CANDIDATE_UNCONFIRMED
    self_mask_enabled = False
    self_identity_confirmed = False
    mask_applied = False
    candidate_cells = 候选逐格资料
```

这三个 False 分别强调：默认没有启用屏蔽、没有确认自身身份、没有对现场应用过滤。函数只返回资料，不在这里写文件，也不发布 ROS 消息。

## 4.10 函数 run 和 main

run 是文件接口，analyze 是计算主体，main 是命令行入口。这样可以只拿 analyze 做教学或测试，不必先建立文件夹、开启雷达或 ROS。

```text
run：
    计算输入 NPZ 文件的 SHA256
    用 allow_pickle=False 读取数组
    调用 analyze
    再计算输入 SHA256，不一致则报错
    把来源指纹写入结果
    新建输出目录，已存在则报错
    写 candidate_review.json 和 candidate_voxels.csv
    返回结果

main：
    读取输入路径、坐标系、输出位置和可选参数
    调用 run
    常见输入或文件错误时打印错误并退出
    成功时打印摘要及 SAVED_DIRECTORY
```

SHA256 是文件字节的指纹，用于核对是否拿了同一份文件。它不证明点属于身体。只调整 JSON 排版也可能改变文件指纹，所以审核记录必须对应当时生成的那份候选文件。

# 5 用同一组教学数据走完全过程

以下 A、B 的身份是教学假设，不是算法识别结果。例子中初始化选中 100 帧，每段 20 帧；文件另有一帧在 10.1 s，使整段覆盖初始化末端。

## 5.1 构造四种出现方式

| 点组 | 示例位置或索引 | 100 帧中出现情况 | 预期候选 |
| A | [0.205,0.005,0.005]，格 [10,0,0] | 各段 17 帧，共 85 帧 | 是 |
| B | [-0.205,0.005,0.005]，格 [-11,0,0] | 五段各 20 帧，共 100 帧 | 是 |
| C | [0.305,0.005,0.005] | 只在最开始 10 帧 | 否 |
| D | [0.105,0.045,0.005] | 前四段都有，最后一段没有，共 80 帧 | 否 |

```text
A：总出现率 = 85 / 100 = 0.85
   每段 = 17 / 20 = 0.85
   总门槛和五段门槛都通过

B：总出现率 = 1.00，各段也都是 1.00
   通过；即使我们在教学中把它假设为外部桌面

C：总出现率 = 0.10，不通过

D：总出现率 = 0.80，通过总门槛
   最后一段出现率 = 0 / 20 = 0
   不通过五段门槛，所以不是候选
```

如果给 A 在某一帧追加 20 个重复点，A 的出现率仍然是 85%，不会变成 105%。点数增加和出现帧数增加不是一回事。

## 5.2 教学审核

假设经过另有依据的核对，我们决定 A 是固定结构、B 是外部目标。程序本身没有完成这个身份判断。

```text
A 的审核记录：
    voxel_index = [10,0,0]
    decision = SELF
    reason = 教学假设此区域已核对为固定结构

B 的审核记录：
    voxel_index = [-11,0,0]
    decision = EXTERNAL

整体审核依据 = 这是一组教学假设
```

make_profile 只把 A 放进 self_voxels。B 虽然更加稳定，也不排除。UNSURE 同样继续保留，这说明稳定性和最终排除之间还有审核这个环节。

## 5.3 对七个输入点计算标记

显式启用本次预览后，按如下输入顺序检查。这里的 NaN 只是为了演示 preview 对任意点数组的处理；真实近点 NPZ 的 checked_sample 会先拒绝含 NaN 的导出。

| 序号 | 输入 | self_removed | invalid | kept |
| P0 | [0.205,0.005,0.005]，A 格内 | True | False | False |
| P1 | [-0.205,0.005,0.005]，B 格内 | False | False | True |
| P2 | [0.225,0.005,0.005]，A 的相邻格 | False | False | True |
| P3 | [0,0,0] | False | True | False |
| P4 | [NaN,0,0] | False | True | False |
| P5 | [0.1,0,0]，没有选中的近点 | False | False | True |
| P6 | [0.105,0.045,0.005]，D 位置 | False | False | True |

所以排除 1 个自身选择区的点、无效 2 个、保留 4 个。P5 很近但仍保留，说明这份体素预览不是“所有 0.2 m 内点都删掉”。P6 不是候选，也没有被审核为排除区，所以继续保留。

如果 enabled=False，P0 也不会按自身区域排除，五个有效点都会保留；P3、P4 仍单独标为无效。

# 6 审核工具如何把决定变成配置

## 6.1 函数 digest

```text
读取指定文件的字节
用 SHA256 算法计算指纹
返回十六进制字符串
```

digest 不读取点的几何意义，只读文件字节。它用于候选与 NPZ 的对应、审核与候选的对应，不是识别算法。

## 6.2 函数 checked_candidate

```text
确认版本为 1，kind 为初始化体素候选
确认 enabled、identity_confirmed、mask_applied 都是 False
确认坐标系名称非空
确认格宽在 0.005 至 0.1 m

候选必须是列表，数量不能超过 100000
对每格：
    索引必须是三个普通整数，绝对值不超过 1000
确认没有重复格，声明候选数量与实际列表长度一致
返回 坐标系、格宽、所有索引
```

这个函数检查的是用于审核的“候选格式”。已经启用的配置、旧 C++ 盒子配置以及另一个阶段的审核配置都不能冒充它。中心和出现率用于显示，但排除范围的主要依据是体素索引与格宽。

## 6.3 函数 make_profile 的来源和完整性检查

```text
先调用 checked_candidate
审核版本必须是 1
审核所带的候选指纹必须与当前候选指纹相同
审核记录数量必须等于候选数量

建立候选索引集合 lookup
建立空集合 seen 和空列表 accepted
```

数量相同还不够。例如两条审核都写 A、遗漏 B，仍然不完整，所以循环中还要检查有没有重复、有没有候选之外的索引。

## 6.4 逐格处理三个决定

```text
对每条审核记录：
    索引必须合法、属于候选，并且以前没有处理过
    将索引放入 seen
    decision 只能是 SELF、EXTERNAL 或 UNSURE
    reason 必须是文本

    如果 decision 是 SELF：
        理由不能为空
        把索引加入 accepted
    如果是 EXTERNAL 或 UNSURE：
        不加入 accepted
```

程序不会把没有选进排除区的点自动标成“外物已识别”。它只是继续保留；UNSURE 的身份仍不知道。

## 6.5 返回配置中的字段

```text
如果 accepted 非空，总审核依据也必须非空

返回：
    kind = reviewed_sensor_voxels
    frame = 候选的坐标系
    voxel_m = 候选格宽
    self_voxels = 排序后的 accepted
    self_mask_enabled = False
    self_identity_confirmed = accepted 是否非空
    confirmation_basis = 审核者声明 或 未确认
    masked_space_occupancy = unknown_not_free
```

self_identity_confirmed 在这里仅表示存在显式的审核接受声明。代码不会核实理由是否符合物理事实；测试夹具也能模拟这个字段，所以不能只看它为 True 就宣称身体识别成功。

unknown_not_free 表示屏蔽或遮挡的空间仍然未知。删除点不会自动给你一块已经证明安全的空地。

## 6.6 函数 make_page

```text
读取候选 JSON，检查格式
候选里的 input_sha256 必须等于这份 NPZ 的指纹
调用 checked_sample 检查 NPZ
只取初始化窗口内的近点作为背景

背景点过多时，按固定间隔抽样到最多约 6000 点
候选体素列表不抽样
把数据填入 HTML 模板，转义可能影响脚本标签的字符
以新文件方式写 HTML，已有同名文件则报错
```

背景抽样只影响显示，不重新计算候选，也不改变过滤精度。页面只展示近点数据，不是完整三维环境。X-Y、X-Z、Y-Z 是同一组点的三个投影，单张投影中重合的位置可能有不同的第三维坐标。

## 6.7 浏览器模板实际负责什么

self_review_template.html 是配套页面，不是第四个 Python 算法。浏览器里的 JavaScript 负责画投影、选择格子、修改决定和导出审核 JSON。默认把所有格子标为 UNSURE；标 SELF 时要求本格理由和总审核依据。

点击导出只是生成一个下载文件，不会给 Jetson 发控制命令。Python 之后仍会检查这份下载记录，不能只依赖网页上的表单检查。当前页面生成与脚本语法已检查，交互和下载尚未实际验证。

# 7 局部过滤函数究竟做了什么

## 7.1 两个容易混淆的开关

| 字段或参数 | 当前含义 |
| profile.self_mask_enabled=False | 审核资料保持默认关闭；预览接口要求它仍为 False |
| preview 的 enabled=False | 这一次函数调用默认不做局部排除 |
| preview 的 enabled=True | 显式进行离线排除预览，不等于启动现场屏蔽 |

这里并不是把 profile.self_mask_enabled 改为 True 才能预览；当前接口反而会拒绝已经开启的资料。命令行 preview 模式明确传 enabled=True，但输出仍标 live_mask_applied=False。

## 7.2 先检查配置

```text
检查 enabled 是布尔值
配置版本和 kind 必须正确
配置必须仍默认关闭
输入点的坐标系必须等于配置坐标系
格宽、self_voxels 每个索引必须合法

如果本次 enabled=True，且有要排除的格子：
    必须存在明确的接受声明、声明来源和总审核依据
    否则报错
```

如果没有任何接受的格子，显式预览也不会凭空删除点。坐标系检查不等于做了 TF 变换；错坐标系会报错，而不是自动转换。

## 7.3 建立有效点标记

```text
xyz = 把输入整理为数值 N×3 数组
finite[i] = 第 i 个点的三个坐标是否都有限
zero[i]   = 此点有限，并且三个坐标全是 0
valid[i]  = finite[i] 并且不是 zero[i]

removed = 长度 N、初始全为 False 的数组
```

这一步把无效点单独分类，没有把它们说成“身体”。例如一个 NaN 点的 invalid=True，但 self_removed=False。

## 7.4 判断点是否落入选中的格子

```text
如果本次 enabled=True 并且排除格集合非空：
    只对有效且处于可索引范围的点计算体素索引
    对每个这类点：
        key = floor(点坐标 / 格宽)
        如果 key 在接受的格子集合中：
            removed[此点] = True
```

可索引范围是每个坐标绝对值不超过 1001×格宽。默认格宽 0.02 m 时约为 20.02 m。这个数不是身体半径或提醒范围，而是配合索引上限避免巨大坐标转整数溢出；更远有限点不可能匹配这些限定索引，继续保留。

这里没有 PCL 邻域过滤、0.2 m 近点下限或地面识别，也没有求最近距离。不要把原 C++ 的处理步骤想当然套进此函数。

## 7.5 返回三个布尔数组

```text
self_removed = removed
invalid      = 不是 valid
kept         = valid 并且不是 removed
返回上述三个数组及“屏蔽空间未知”的说明
```

布尔数组是一排 True/False，位置与输入点一一对应。它们是决定如何选择点的标记，输入 xyz 本身没有被删除或覆盖。

如果调用者以后要构造新点云，可以按 kept 选择输入行；这是如何使用结果的解释。当前 main 的 preview 路线只统计这些标记并写摘要，没有导出过滤后的 PCD、NPZ 或实时点云话题。

## 7.6 函数输入范围和命令输入范围不完全相同

preview 函数可以处理任意距离的有限数值点，按体素决定是否排除。可是当前命令行 preview 先对 near_returns.npz 调用 checked_sample，因此命令路径仍只接受约 0.5 m 内的近点导出。

刚才完整 bag 的验证脚本是逐帧直接调用 preview，才检查到了完整点云里的更远点。不能把那份测试脚本误认为已经实现了实时 ROS 节点。

## 7.7 main 的两条执行路线

```text
读取子命令
如果子命令是 page：
    调用 make_page
    打印保存的 HTML 路径
    结束

如果子命令是 preview：
    读候选和审核 JSON
    用 make_profile 构造审核配置
    核对 NPZ 来源指纹，检查近点数据
    调用 preview，显式 enabled=True
    统计会排除、保留、无效的点数
    新建目录，写配置与统计 JSON
```

两个子命令是同一文件的两种用途，不是运行一次就先生成页面、等人审核、再自动过滤。当前仍需要分别运行并交接审核文件。

# 8 旧审查工具的其余函数

这一章覆盖 audit_mask_risk.py 中尚未解释的函数。新初始化通常只借用 checked_sample；以下大部分函数属于之前的“局部盒风险审查”。它们保留在文件里，并不表示新体素程序每次都会使用。

## 8.1 函数 checked_boxes

```text
输入盒子列表不能为空
每个盒子必须包含 min 和 max
min/max 都是三个有限数字，各坐标绝对值不超过 1000
将边界转成 float32
确认转换后每个轴仍满足 min < max
返回所有盒子的上下界数组
```

转换后再比较，是为了避免非常接近的上下界在 float32 中变成同一个数。这里只检查几何是否可用，不检查其中是否都是自身点。

## 8.2 函数 removed_by_boxes

```text
检查输入点为有限 N×3 数组
removed 全部初始化为 False

对每个盒子：
    对每个点：
        如果 x、y、z 都在各自 min 至 max 之间：
            removed[该点] = True
返回 removed
```

旧盒子比较包含 min 和 max 的六个面；多个盒子按“或”合并，重叠点只记为一个被删点。新体素用 floor，其数学区间是左闭右开。盒子边界规则与体素边界规则不同，不能混用来手算测试结果。

## 8.3 函数 partition_counts

```text
选出 first <= 点的帧序号 < end 的点
按帧分别统计总近点数和 removed 为 True 的点数
相减得到剩余点数
再统计：无近点帧数、全删帧数、逐帧删除最小/平均/最大
返回这一段统计
```

first/end 是帧序号区间，不是秒数。比如 [0,3) 包含第 0、1、2 帧，不包含第 3 帧。没有点的帧也应留在统计里；“没有点”与“原来有点但全删了”不同。

这个函数依赖调用者给出有效的非空帧区间，并不是针对任意 first/end 都有完整独立检查的通用接口。

## 8.4 函数 synthetic_risks

它构造四组人工几何场景，返回哪些点会被旧盒子删除。人工点不是实测雷达回波，也没有被写进原始 bag。

| 场景 | 构造方法 | 检查意义 |
| 盒内细杆 | 在盒里放 9 个杆状点 | 外物也可能被整根删掉 |
| 跨盒细杆 | 9 个点中两端超出盒子 | 预期中间 7 点被删，端点保留 |
| 六个边界面 | 每个盒面放 1 点 | 检查边界包含规则 |
| 刚好超出盒面 | 各向外移一个 float32 步长 | 检查极近边界外点是否保留 |

## 8.5 函数 audit

```text
要求旧盒子候选仍 disabled 且 identity_confirmed=False
检查盒子、margin 和近点数据

把整个记录按帧数分为前半段与后半段
用前半段近点的逐轴最小/最大值，加 margin 拟合一个盒
分别计算：
    原候选盒在所有点上会删多少
    新拟合盒在前半段会删多少
    新拟合盒在后半段会删多少
加入人工几何反例与限制说明
返回审查报告
```

默认 margin 是 0.02 m，扩大盒子不是提高识别准确率。前半段拟合、后半段检查仍是同一记录；它不能证明另一背景或另一穿戴状态也成立。

这里的“分半”与新初始化的“前 10 秒”是两种不同实验设计。旧 audit 要求 self_boxes 和 self_mask_frame，新体素候选有 candidate_cells 和 frame，不能把新候选 JSON 直接传给旧 audit。

## 8.6 函数 public_summary 和 main

public_summary 从旧报告中去掉拟合盒 prefix_fitted_box。旧 main 在生成公开汇总前，还会另外去掉输入 NPZ 和候选的指纹。不能只调用 public_summary 就假定任何未来新增字段都完成了隐私审查。

```text
旧工具 main：
    读取 sample、candidate、output 三个路径
    加载近点数组和 JSON 格式的旧盒子候选
    调用 audit
    给私有报告加输入文件指纹
    新建输出目录
    写私有报告
    去掉拟合盒，再去掉输入指纹
    写汇总并打印
```

候选文件由 json.loads 读取，不是通用 YAML 解析器。某些旧文件虽然扩展名是 .yaml，实际内容是 JSON，才能由这条路径读取。

# 9 命令入口和刚才的实测怎样理解

## 9.1 用帮助命令认识参数

Jetson 最新完整工具目录是 ~/haptic_ws/tools/self_review_20261023。只查看帮助不需要开启雷达或 ROS master。

```text
cd ~/haptic_ws/tools/self_review_20261023
python3 initialization_candidates.py --help
python3 review_self_mask.py --help
python3 review_self_mask.py page --help
python3 review_self_mask.py preview --help
```

这些是帮助命令，只显示用法。下面的流程示意中，中文占位路径必须换成实际文件位置，不能原样执行。

```text
python3 initialization_candidates.py 输入.npz
    --frame 实际坐标系 --output 新候选目录

python3 review_self_mask.py page
    --candidate 候选.json --npz 同一输入.npz --html 新页面.html

在浏览器中审核，下载审核决定 JSON

python3 review_self_mask.py preview
    --candidate 候选.json --npz 同一输入.npz
    --decisions 审核决定.json --output 新预览目录
```

上述换行是为了阅读，不是可直接粘贴的多行 shell 命令。main、run 等函数名不用在终端逐个敲；命令入口会按程序安排调用它们。

## 9.2 哪些参数改变什么

延长 seconds 会改变统计时间窗，但需要输入记录足够长。减小 voxel_m 会细分空间，也会使抖动更容易跨格。提高 occupancy 会减少一些候选，但不能自动把墙面变成非自身。放宽 max_gap 会接受更不连续的记录，不是让雷达真的少丢帧。

这些参数决定候选统计条件，不是震动强弱系数。本手册只解释，没有修改这些参数或运行配置。

## 9.3 刚才 30 秒记录的真实检查

实际得到 291 帧完整点云，消息时间跨度约 29.000338 s。前 10 秒 101 帧提取了 180 个候选体素，再检查后面的 190 帧。

| 条件 | 后续 190 帧的结果 | 证明什么 |
| 默认未确认 | 排除 0 点 | 不擅自把稳定候选当作自身 |
| 内存中模拟接受候选 | 排除 146816 点，保留 2227822 个有效点 | 局部过滤按测试范围执行 |
| 区域外 | 删除 0 点 | 本次几何范围没有扩到选中格外 |
| 人工格内与格外控制点 | 格内 12 点全排除，格外 12 点全保留 | 基本成员判断符合预期 |

模拟审核的 SELF 和确认字段只是测试输入，不是一次真实人工身体标注。测试没有把这种配置保存成日常默认屏蔽。前后数据来自同一次记录，不能当独立场景验证；区域外删除 0 不是实际物体误报或漏报率。

记录、驱动和临时 master 已停止，功能程序与默认设置保持。第一阶段真正的现场目标还缺身份核对、实时接入和外物对照。现在应说“候选与局部排除原型已验证”，不能说“已经自动识别使用者”。

## 9.4 这三个文件分别不负责什么

| 不负责的事情 | 应当怎样理解 |
| 直接读取实时 Livox 消息 | 当前输入主要是导出的文件，实时适配尚未写入 |
| 启动 Point-LIO 或雷达驱动 | 开工具不等于开驱动或建图 |
| 自动辨认身体与桌面 | 稳定性不足以提供这种身份 |
| 输出最近距离或震动强度 | 属于下一步策略或原 C++ 节点 |
| 输出过滤后的 ROS 点云 | 当前 preview 只返回标记并保存统计 |
| 根据停留时间减弱震动 | 速度与时间阶段尚未实现 |

# 10 读懂数组以及检查自己的理解

## 10.1 常见 NumPy 写法翻译表

| 写法 | 中文含义 |
| np.asarray(x) | 把输入当作数组处理，不保证一定复制 |
| astype(np.float64) | 转成双精度浮点数组参与计算 |
| xyz.shape | 查看数组的行列尺寸 |
| xyz[条件] | 只选条件为 True 的行，形成选取结果 |
| floor(x / s) | 求 x 对应的格子索引，向负无穷方向取整 |
| column_stack | 把多个一维或二维数据按列拼在一起 |
| unique(..., axis=0) | 把完全重复的行合并 |
| return_inverse=True | 告诉你每条记录对应去重后哪一个编号 |
| bincount | 统计每个非负整数编号出现多少次 |
| add.at | 按给定索引累加，重复索引也逐次累计 |
| all(..., axis=1) | 对每一行判断是否每个条件都成立 |
| any(...) | 是否至少有一个条件成立 |
| A & B | 两个布尔数组逐位置做“并且” |
| 按位或运算符 | 两个布尔数组逐位置做“或者”，源码符号为竖线 |
| ~A | 布尔数组逐位置取反 |
| int(布尔数组.sum()) | 统计 True 的数量 |

对于 NumPy 布尔数组，不能随便把 & 和 ~ 改写成 Python 对单个对象使用的 and、not。

axis=1 常表示沿每一行的列进行汇总。例如每个点的三个坐标都有限，结果是一点对应一个布尔值。unique 的 axis=0 表示比较整行；在 [ix,iy,iz,帧号] 记录里，四个数都相同才算重复。

## 10.2 逐步问答

问题 1：一个格子只在一帧出现，但这一帧有 1000 个点，能算出现 1000 帧吗？
答案：不能。按“格子、帧序号”去重后只算一次。点密集不等于时间稳定。

问题 2：桌面在 10 秒里一直被扫到，会不会成为候选？
答案：会。候选统计不识别物体身份，需要后续审核或其他证据。

问题 3：稳定候选有 80% 出现率，是 80% 概率属于身体吗？
答案：不是，它只是出现帧数除以总帧数。

问题 4：默认未确认，同时调用 preview(enabled=True)，会自动排除所有候选吗？
答案：不会。审核配置没有接受的 self_voxels，仍然没有要按自身排除的格子。

问题 5：预览配置 self_mask_enabled=False，为何显式预览还能得到排除标记？
答案：配置保持关闭是离线资料约定，enabled=True 只允许本次计算预览；没有开启现场节点。

问题 6：无效点数增加，能说排除了更多身体吗？
答案：不能。invalid 与 self_removed 是不同标记，要分开统计。

问题 7：新外物进入已经选作排除区的同一小格，会怎样？
答案：几何匹配仍可能排除它。当前方法不能在同格内区分身份。

问题 8：NPZ 的 frame_id=[0,1,2] 是三个空间坐标系吗？
答案：不是，是点所属的帧序号。空间坐标系名称存放在 frame_names。

问题 9：只把候选 JSON 重新排版，为什么旧审核记录可能不能再用？
答案：SHA256按文件字节计算，字节变化会改变指纹；记录绑定的是那份候选文件。

问题 10：原 C++ 的 launch 能自动启动这些 Python 工具吗？
答案：当前不能。这套工具是独立离线入口，尚未连接到实时 launch。

问题 11：体素右边界与旧盒子 max 面的包含规则相同吗？
答案：不同。体素按 floor，数学上右边界不包含；旧盒子比较包含 max 面。实际浮点边界还要考虑表示误差。

问题 12：preview 返回 kept 后，原始 xyz 和 bag 已经删点了吗？
答案：没有。kept 是选择标记；当前 CLI 只统计并保存配置与摘要，不改原始数据。

## 10.3 对照源码时按这个顺序找

先读 initialization_candidates 的 main、run、analyze；需要理解检查时跳到 audit_mask_risk 的 checked_sample。再读 review_self_mask 的 main，分别沿 make_page 和 make_profile、preview 两条路线。最后读 audit_mask_risk 其余函数，理解它们为什么属于旧风险审查而非新主线。

不要按文件从第一行一路硬读完才去看下一个。先知道“现在调用的是哪个函数”，再追它的输入输出，会更容易把每一行放回完整流程里。
